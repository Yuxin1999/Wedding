# 从本机体验到两个人一起用

**已经有 AppID、还没开云开发？** 直接按[双人体验版操作指南](couple-quickstart.md)完成开通、数据库、云函数、上传体验版和伴侣加入。

## 1. 注册与导入

在[微信公众平台](https://mp.weixin.qq.com/)注册“小程序”，按平台当前要求完成主体信息、类目及备案。拿到小程序 **AppID** 后，在微信开发者工具的项目详情中使用它，并更新根目录 `project.config.json` 的 `appid`。

AppID 和云环境 ID 是项目标识；AppSecret、上传私钥、账号登录信息是凭证，不能提交到仓库。本项目直接在开发者工具中操作上传，不需要在这里填写 AppSecret 或 CI 上传私钥。

只有电脑体验时，可以继续保留 `touristappid` 和空云环境配置。

## 2. 开启云开发

1. 用这个小程序 AppID 打开项目，在开发者工具中进入“云开发”，按当前平台套餐和计费规则创建环境。
2. 复制环境 ID，填入 `miniprogram/config.js`：

   ```js
   module.exports = { cloudEnv: '填写你的云环境ID' };
   ```

3. 在云数据库控制台创建以下三个集合，名字必须一致：

   | 集合 | 用途 |
   | --- | --- |
   | `wedding_users` | 微信身份与所属空间映射 |
   | `wedding_spaces` | 两人共享的设置、任务、预算及版本号 |
   | `wedding_invites` | 邀请码摘要与到期时间 |

4. **每个集合**的客户端权限都设成“所有用户不可读写”，或选择自定义规则并填入 `cloudfunctions/database.rules.json` 的内容：

   ```json
   { "read": false, "write": false }
   ```

   所有读写经云函数完成。不要设成“所有用户可读写”；云函数从 `getWXContext().OPENID` 识别身份，不接受客户端自报用户 ID 或空间权限。过期邀请记录可以在控制台按 `expiresAt` 清理，业务代码仍会校验过期时间。

5. 在项目 `cloudfunctions/wedding` 上选择云环境，部署 `wedding` 云函数，采用开发者工具支持的“上传并部署：云端安装依赖”。使用云开发当前支持的 Node.js 18 或更新运行时；本机开发工具使用 Node.js 20+。
6. 如果选择把本机已安装依赖上传，先在 `cloudfunctions/wedding` 执行 `npm ci`。不要把 `node_modules` 提交进 Git。函数无需公开 HTTP 入口。
7. 重新编译小程序，在“我们”页会出现创建 / 连接空间和加入入口。

云函数写操作通过事务更新，绑定最多两人；保存时校验数据版本。冲突时刷新页面数据并保留输入，用户确认后重试。设置、任务和预算保存在一份受保护的空间文档中，任务和开支分别最多 300 条。

## 3. 让伴侣加入

更新到包含“自定义分类 / 预算关联安排 / 付款日期”的版本时，请将整个 `cloudfunctions/wedding` 重新上传并部署（包括生成的 `domain.js`），然后更新双方的小程序。旧云函数不认识新字段和分类操作，可能拒绝保存或丢失新字段。已有本机及云端记录无需清空，分类自动补齐原有六项，关联和日期默认留空。更新双方客户端后再开始调整分类，避免旧客户端的固定分类列表无法使用新增的分类。

付款提醒在首页和预算页内展示；未配置订阅消息模板，也没有定时云任务，因此不会在关闭小程序后主动发送微信提醒。需要微信消息通知时，还需配置真实 AppID、合适的订阅消息模板、用户订阅授权与云端定时发送流程。

1. 你先在“我们”填写两个人的称呼和婚期，然后点“创建 / 连接共同空间”。首次创建会复制当前本机计划；重新连接已有空间时读取原有云端计划。
2. 点“邀请我的伴侣”，发邀请卡片或复制 12 位邀请码，通过你们自己的聊天发给对方。邀请码 7 天内有效；重新生成后旧码和旧卡片失效。
3. 在小程序后台为伴侣添加体验成员或开发成员，按平台要求通过真机预览 / 体验版让伴侣进入同一个小程序。
4. 对方打开邀请卡片并确认加入，或选择“加入伴侣的空间”填写邀请码。不要先创建另一个空间。
5. 两人分别修改任务或预算，另一方打开页面或下拉刷新查看；前台页面每 15 秒自动检查更新，编辑时暂停、后台停止。

加入不会删除对方原有本机记录，也不会将两边的本机数据自动合并。切回本机模式不代表退出绑定。暂未实现解绑、更换伴侣、文件附件、微信订阅消息提醒或支付。

## 4. 编译和真机验收

在微信开发者工具完成以下操作，再用 iOS / Android 真机确认弹层和键盘布局：

- 初次进入婚期为空；填写称呼、未来婚期、预算后，首页倒计时和默认任务日期正确。
- 新增任务，分配给对方，设置日期与备注；完成、重新打开、按人筛选、删除。
- 修改婚期：默认相对日期随之变化，手动设置的任务日期不变。
- 新增开支，分别填写预计和已付金额；检查分类汇总、修改 / 删除、超预算提示。
- 首页分类应为紧凑双列；点“新增分类”自定义名称并选图标，清单和预算中应可直接选用。改名后原记录同步更新；重新进入仍保留。管理分类和图标选择面板可滚动，长分类名不撑破卡片。
- 重启小程序后本机数据保留；复制摘要能得到已填写的内容。
- 云端用两个不同微信身份加入同一空间；双方编辑后刷新可见。
- 两台设备停留在同一旧版本后同时保存，较晚提交一方收到冲突提示；对方的数据不被悄悄覆盖。
- 使用第三个微信身份或过期 / 旧邀请码加入应失败；普通客户端不得直接读写数据库。
- 云端断网后保存应提示失败，不能出现“已保存”或悄悄退回本机模式。

仓库的 Node 测试用内存存储模拟事务和微信页面 API，验证业务行为；它们不证明真实微信网络、云权限配置和数据库事务已经部署成功。

## 5. 上传到微信

确认真实 AppID、云开发配置和真机验收后，在微信开发者工具点击“上传”，填写版本号与版本说明。再去微信公众平台“版本管理”设为体验版，或按要求提交审核、发布。

发布前按平台当前要求完善小程序名称、图标、介绍、类目、备案与用户隐私保护指引。若只给你们两人先试用，可以先使用体验版并添加双方为体验成员。

本次生成代码没有执行上传、提交审核、发布或任何会创建付费云资源的操作。

## 依赖说明

前端没有第三方 npm 依赖。云函数固定使用 `wx-server-sdk@4.0.2`，保留安装锁文件和校验。当前 SDK 的间接依赖仍有 `npm audit` 通报（Axios、lodash.set / lodash.unset 及上游依赖链）；没有通过不兼容的强制降级或覆盖来隐藏它们。部署前关注腾讯 SDK 更新，并在升级后复测真实云事务。本应用不允许用户控制数据库字段路径或对外请求地址。
